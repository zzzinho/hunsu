## 1. Context and scope

hunsu 는 HTML 로 디자인하는 로컬 도구다. "HTML 을 쓰는 Figma". 디자인 한 장이 HTML 파일 하나이고, 사용자는 브라우저에서 렌더를 보며 원본을 고치거나 LLM 에게 말로 고치게 한다.

- 실행: macOS 단일 실행파일 `./hunsu [폴더]`. `127.0.0.1:7777` 에 서버를 띄우고 브라우저를 연다. 로컬 전용이다.
- 수정 경로 네 가지가 모두 같은 파일을 고친다: 내장 에디터, 브라우저 채팅(LLM provider), 외부 에이전트(MCP), 외부 에디터.
- LLM 은 hunsu 밖에 있다. 브라우저 채팅은 `llm.Provider` 로 외부 CLI 를 실행하고(PoC: `claude -p`), 외부 에이전트는 MCP 로 들어온다.
- 범위: 현재 구현(MVP, provider 분리, MCP, 프롬프트 캐시 배치)과 v1 계획.

**제약** (`CLAUDE.md`)

| 제약 | 설계에 주는 영향 |
|---|---|
| 외부 의존성 0: Go 표준 라이브러리만, 프론트엔드는 빌드 없는 JS + CodeMirror 5 | MCP·파일 감시·버저닝을 직접 구현한다 (A10, A13, A15) |
| SRP, OCP | 변하는 지점만 작은 인터페이스로 둔다: `llm.Provider`, 진행 이벤트 해석, 시계·ID |
| 핵심 패키지는 특정 LLM·에이전트를 전제하지 않는다 | provider 패키지는 `main.go` 만 참조한다. 모델 이름 같은 고유 값은 provider 안에 둔다 |
| TDD, 테이블 테스트가 설명서 | 5.5 |

## 2. Goals and non-goals

**Goals**

| 목표 | 상태 |
|---|---|
| 파일 수정이 렌더에 바로 반영된다 (에디터·LLM·외부 에디터 모두) | 구현 |
| LLM 이 일부 수정, 페이지 재디자인, 새 페이지, 여러 페이지, 빈 폴더 전체 생성을 한다 | 구현 |
| 진행 상황이 보인다. 큰 파일을 쓰는 1분 넘는 구간도 포함 | 구현 |
| 렌더 화면에서 요소를 골라 "이거" 로 지정한다 | 구현 |
| 모든 페이지와 LLM 이 디자인 시스템(`DESIGN.md` + `design.css`)을 공유한다 | 구현 |
| 대화가 이어지고, 요청 하나를 통째로 되돌린다 | 구현 |
| 특정 LLM 에 묶이지 않는다: provider 교체, MCP 클라이언트 중립 | 구현 (provider 는 1종) |
| 다른 사람이 설치해서 혼자 디자인을 만들고 전달한다: Homebrew 설치, provider 로그인 확인, 에셋, 내보내기, 버전 | (v1) |
| LLM 이 렌더 결과를 본다. 비교안, 텍스트 직접 수정, 영어 UI, Codex provider | (v1) |

**Non-goals**

- 서버 배포, 협업·클라우드. 로컬 단일 사용자 도구다.
- 무한 캔버스·다중 프레임 (A19), 컴포넌트·레이어, 속성 패널 (A18), 디자인 시스템 전용 편집 화면.
- hunsu 가 API 키를 보관하는 것. 각 provider CLI 의 로그인을 쓴다.
- hunsu 가 MCP 로 파일 쓰기 도구를 주는 것 (A14).
- 코드 서명·공증 (A16), Windows.

## 3. Design

### 3.1 개요

hunsu 는 파일을 원본으로 두고 세 가지만 얹는다.

1. **렌더와 편집**: 디자인 폴더를 iframe 으로 서빙하고, 바뀐 파일을 폴링으로 감지해 다시 그린다.
2. **LLM 오케스트레이션**: 프롬프트 조립(컨텍스트 관리), 동시 실행 막기, 요청 직전 스냅샷, 진행 이벤트 중계. 파일 수정 자체는 LLM 이 자기 편집 도구로 한다.
3. **브라우저 상태 공유**: 보이는 페이지와 선택한 요소를 MCP 로 외부 에이전트에게 준다.

LLM 과의 경계는 두 개다. hunsu → LLM 은 `llm.Provider`, 에이전트 → hunsu 는 MCP.

### 3.2 시스템 맥락

```
브라우저 (UI + iframe 렌더)
   │ ▲   /api/* (HTTP·SSE), /p/* (디자인 파일)
   ▼ │
hunsu (127.0.0.1:7777)
   ├─ server ─ chat ─ history (.hunsu/)
   │             └─ llm.Provider ──실행·stdin──▶ provider CLI (PoC: claude -p) ──▶ 디자인 폴더 수정
   ├─ ui.Hub: 보이는 페이지, 선택한 요소
   ├─ /mcp ◀──Streamable HTTP + Bearer── 외부 MCP 클라이언트 ──자기 편집 도구──▶ 디자인 폴더 수정
   └─ 0.5초 폴링: 디자인 폴더 변경 → SSE → 렌더·에디터 갱신
```

| 패키지 | 책임 |
|---|---|
| `main.go` | 조립. provider 를 고르는 유일한 곳 |
| `internal/project` | 디자인 폴더 접근, 폴더 밖 차단, 템플릿, 공용 디자인 규칙 |
| `internal/watch` | 파일 변경 감지 |
| `internal/llm` | provider 계약 |
| `internal/claude` | PoC provider |
| `internal/chat` | 요청 처리: 잠금, 프롬프트 조립, 대화 이어가기, 직접 고친 파일 알림 |
| `internal/history` | 스냅샷과 되돌리기 |
| `internal/server` | 브라우저용 HTTP API |
| `internal/ui` | 브라우저 화면 상태와 명령 |
| `internal/mcp`, `internal/mcptools` | MCP 서버·인증, hunsu 도구 |
| `web/` | 브라우저 UI. 판단 로직은 순수 함수 모듈 |

### 3.3 핵심 결정

**원본과 렌더**

| 결정 | 이유 | 감수하는 것 |
|---|---|---|
| 디자인 = 루트의 `.html` + `DESIGN.md`·`design.css` + `assets/` 의 이미지·폰트. 숨김 파일·심볼릭 링크 제외 | 브라우저가 그대로 렌더·적용한다. 변환 단계가 없다. 모든 페이지가 같은 경로로 `design.css`·에셋을 링크한다 | 하위 폴더 페이지 없음. 페이지 CSS·JS 는 인라인 |
| 변경 감지 = 0.5초 폴링. 열린 파일, 보이는 페이지, `design.css` 만 (A10) | LLM·에디터·외부 에디터 수정을 한 방법으로 잡는다. 의존성 없음 | 최대 0.5초 지연. 감시 대상이 늘면 비용도 는다 |
| hunsu 의 저장 = 임시 파일에 쓰고 이름 바꾸기 | 렌더나 LLM 이 반쯤 쓴 파일을 읽지 않게 | 없음 |
| 파일 API = 이름 규칙 + 일반 파일만 + `os.Root` (A11) | 폴더 밖 접근을 OS 수준에서 막는다 | 규칙 밖 파일은 다룰 수 없다 |

**LLM provider**

| 결정 | 이유 | 감수하는 것 |
|---|---|---|
| `llm.Provider` 하나 뒤에 실행·이벤트 해석·모델·격리를 가둔다. 고르는 곳은 `main.go` 하나 | Anthropic API, Codex 등을 핵심 패키지 수정 없이 추가한다 (OCP) | 공통 이벤트로 줄이며 provider 고유 정보(비용 등)는 버린다 |
| LLM 이 자기 편집 도구로 파일을 직접 고친다 (A4) | 바뀐 부분만 쓴다. 작은 수정 7초대 | 편집 도구가 없는 API 형 provider 는 폴더로 한정된 파일 도구와 도구 호출 루프를 provider 안에 구현하고, 격리도 provider 가 보장해야 한다 |
| 진행 = 부분 스트리밍을 공통 이벤트로 변환. 쓰는 중에는 1KB 마다 크기 (A7) | opus 가 큰 파일을 쓰는 80초 동안 완성 메시지 이벤트가 없다 | 조각난 도구 입력을 이어 붙이는 해석기. provider 안에 둔다 |
| claude provider 격리: `--safe-mode --strict-mcp-config --restricted --tools Read,Edit,Write --permission-mode acceptEdits` (A8) | 명령 실행 없이 폴더 안 파일만 다룬다. 사용자 설정·hook·MCP 를 섞지 않아 2배 빠르고 10배 싸다 | 사용자의 claude 설정이 반영되지 않는다 |
| 프롬프트는 표준 입력으로 (A9) | `-` 로 시작하는 요청이 플래그로 해석되지 않게 | 없음 |
| 인증 = 각 CLI 의 로그인. (v1) `Status()` 로 설치·로그인을 확인하고 로그인 명령을 안내 (`claude auth status --json`, `codex login status`) | 구독 로그인을 그대로 쓴다. hunsu 는 키를 갖지 않는다 | 로그인은 사용자가 터미널에서 한다 |
| 모델 = provider 가 목록과 기본값(첫 번째)을 정한다. claude: opus 기본, sonnet·haiku | 디자인 품질은 opus. haiku 는 2배 빠르고 20배 싸서 선택지로 둔다 | 기본값이 가장 느리고 비싸다 |

**컨텍스트 관리**

| 결정 | 이유 | 감수하는 것 |
|---|---|---|
| 프로젝트 하나에 대화 하나. 요청마다 현재 페이지를 알린다 (A5) | 새 페이지·여러 페이지 요청이 맥락을 공유한다 | 대화가 길어진다. 그래서 캐시 배치가 중요하다. [새 대화] 로 끊는다 |
| 고정된 것은 system prompt, 바뀌는 것은 요청 끝 (A6) | 프롬프트 캐시는 앞부분이 같아야 재사용된다. 측정상 캐시 비용 약 4배 차이 | 요청 메시지가 길어진다 |
| 디자인 시스템: 대화의 첫 요청(새 대화·서버 재시작 포함)에 전체, 이후에는 사용자가 바꾼 파일만 | 캐시를 깨지 않고 토큰도 아낀다. LLM 이 고친 내용은 LLM 이 이미 안다 | LLM 이 자기 수정을 대화 기록으로 기억한다고 가정한다 |
| `[알림]`: 응답 직후 파일 해시를 기억하고, 다음 요청에서 달라진 파일을 알린다. 되돌리기·외부 에이전트 수정도 포함 | 없으면 예전 내용으로 Edit 하다 실패해 6초가 17초가 된다 | 해시는 메모리에만 있다 (7절 3) |
| 선택한 요소 = 선택자 + HTML 앞 2000자 | `body` 같은 큰 요소는 페이지 전체가 된다. 위치는 선택자로 안다 | 큰 요소는 HTML 이 잘린다 |
| 디자인 규칙은 한 곳(`internal/project/rules.md`). 브라우저 채팅 system prompt 와 MCP 안내문이 공유 | 두 경로의 LLM 이 같은 규칙을 따른다 | 규칙 문구가 두 경로 모두에 맞아야 한다 |

프롬프트 구성 (캐시 배치의 결과라 형태만 적는다)

```
system (고정)   지시문(internal/chat/instructions.md) + 디자인 규칙(internal/project/rules.md)
user (요청마다) [현재 페이지] landing.html
                [알림] 마지막 응답 이후 사용자가 직접 고친 파일: design.css …
                [디자인 시스템] 첫 요청: 두 파일 전체 / 이후: 사용자가 바꾼 파일만
                [에셋] assets/logo.png … (요청마다)
                [선택한 요소] main > section.hero > button.cta + HTML(2000자)
                [요청] 더 크게
```

**외부 에이전트 (MCP)**

| 결정 | 이유 | 감수하는 것 |
|---|---|---|
| hunsu 는 브라우저 상태와 되돌리기 연결만 맡고, 파일은 에이전트가 자기 도구로 고친다 (A14) | 에이전트마다 이미 편집 도구가 있다. hunsu 는 변경을 감지해 다시 그린다 | 에이전트의 편집을 막거나 기록하지 못한다. `checkpoint` 호출은 안내문에 달렸다 |
| 기존 HTTP 서버의 `/mcp`, Streamable HTTP 응답 하나 (A12) | 브라우저 상태를 같은 프로세스에서 공유한다. 서버가 먼저 보낼 메시지가 없어 SSE 는 열지 않는다 | hunsu 가 떠 있어야 한다 |
| 표준 라이브러리 JSON-RPC: `initialize`, `ping`, `tools/list`, `tools/call` (A13) | 도구 호출만 필요하다 | 스펙 변화를 직접 따라가야 한다 |
| 포트 기본 7777 고정, `Bearer` 토큰을 사용자 설정 폴더에 0600 으로 만들어 재사용 | 한 번 등록한 주소·헤더가 바뀌지 않게 | 포트 충돌 시 `-port` 로 바꾸면 재등록해야 한다 |
| 화면 상태는 브라우저가 `POST /api/ui` 로 보낸다. 같은 출처만. 브라우저 명령은 SSE | 상태를 아는 것은 브라우저뿐이다. 다른 사이트가 가짜 선택 요소로 지시를 끼워 넣는 것을 막는다 | 브라우저 여러 개면 마지막 보고가 이긴다 |
| 안내문에 특정 클라이언트의 도구 이름을 쓰지 않는다 | 클라이언트 중립 | 클라이언트별 최적화 없음 |

**되돌리기·버저닝**

| 결정 | 이유 | 감수하는 것 |
|---|---|---|
| 요청·`checkpoint`·복원 직전에 디자인 시스템과 페이지 전체를 `.hunsu/history/<순번>/` 에 복사. 되돌리면 그 뒤 생긴 파일을 지우고 스냅샷을 뺀다. 브라우저 채팅과 MCP 가 같은 스택. 최근 50개 | 요청 하나 = 되돌리기 하나. 단순하다 | 매번 전체 복사, 다시 실행 없음 |
| 내장 타임라인 (A15): 요청이 끝날 때(요청 내용), 요청 전에 사용자가 고쳤을 때('요청 전'), [버전 저장], 복원 때 버전을 남긴다. 직전 버전과 해시가 같으면 남기지 않는다. 복원은 되돌리기 스냅샷을 먼저 남겨 [되돌리기] 로 취소할 수 있다 | 의존성 없고 디자이너도 쓴다. 되돌리기 스택과 나눠 두어 둘 다 단순하다 | 되돌리기와 버전이 같은 상태를 따로 복사한다 (텍스트라 작다). 최근 100개 |
| 버전 썸네일 = 대표 페이지(새로 만든 → 보고 있던 → 첫 페이지)의 첫 화면 1280×800. 버전을 남길 때 바로 찍는다 | 버전마다 무엇이 바뀌었는지 눈으로 고른다 | 요청 끝이 약 0.7초 늦어진다. Chrome 이 없으면 썸네일 없음. 에셋은 버전에 넣지 않는다 |

**화면**

| 결정 | 이유 | 감수하는 것 |
|---|---|---|
| 캔버스 = 파일 1개 미리보기 + 모바일(390px)/데스크톱 너비 (A19) | 원본·LLM 편집이 핵심이다 | 여러 페이지를 한눈에 못 본다 |
| 선택 도구(V)는 클릭을 가로채 링크·버튼이 동작하지 않는다. 손 도구(H)는 3px 이하 움직임을 클릭으로 넘긴다 | 선택과 페이지 동작 확인을 도구로 나눈다 | 페이지 동작을 보려면 도구를 바꾼다 |
| 선택자 = `body` 아래 태그·클래스 2개·같은 태그 형제 순서. 조상에 id 가 있으면 id 부터. 새로고침 후 다시 찾고 없으면 해제 | LLM 이 원본에서 찾을 수 있는 짧은 경로 | 페이지 JS 가 실행 중 붙인 클래스·id 가 들어가면 원본과 안 맞을 수 있다 |
| 외곽선·커서는 렌더된 문서에만 넣는다 | 파일을 건드리지 않는다 | 없음 |
| 실행 중에는 입력·에디터·되돌리기를 잠근다. 보내기 전에 에디터를 저장한다. 취소하면 1초 안에 프로세스를 끝낸다 | 같은 파일을 동시에 고치지 않게 | 실행 중에는 직접 편집 불가 |
| 색감: 바둑. 먹색 바탕, 강조색은 바둑판 나무색(`#e0a64b`) 하나 | 사용자 디자인의 색 판단을 방해하지 않게 | 없음 |
| (v1) 텍스트만 렌더 화면에서 더블클릭으로 직접 수정 (A18) | 문구 수정에 LLM(7초~1분 이상)을 쓰지 않게 | 다른 속성은 LLM·에디터로 고친다 |
| (v1) UI 영어 기본, 설정에서 한국어, 선택 기억 (A20) | v1 은 다른 사람이 쓴다 | 번역 모듈 유지 |

그 밖의 화면 구성: 패널 3개(파일 / 렌더 / 편집기·채팅)는 접고 경계를 끌어 크기를 바꾸며 localStorage 에 기억한다(렌더 320px·편집기 120px 은 남긴다). 확대/축소 25~300%. 모바일은 390px 을 그대로 확대하고, 데스크톱은 브라우저 확대처럼 논리 너비를 바꾼다.

### 3.4 API·계약 (sketch)

**`llm.Provider`**

```go
type Provider interface {
	Run(ctx context.Context, req Request, emit func(Event)) error // req.Dir 의 파일을 직접 고친다. ctx 취소 시 멈춘다
	Models() []Model                                             // 첫 번째가 기본. 비면 화면이 선택을 숨긴다
	// (v1) Status(): 설치·로그인 확인과 안내 명령
}
// Request: Dir, Prompt, SystemPrompt, SessionID(비면 새 대화), Model
// Event:   start(SessionID) · think · read(file) · write(file, size) · answer · tool(text) · retry · reply(text) · fail(text)
// MCPServer: provider 를 만들 때 건네는 도구 서버 (Name, URL, Token)
```

- 대화 ID 는 provider 가 `start` 로 알리고 hunsu 가 다음 `Request.SessionID` 로 돌려준다. hunsu 는 그 값을 해석하지 않는다.
- `chat` 은 `created`(새 페이지), `end` 를, `server` 는 `error` 를 더해 브라우저로 보낸다.

**MCP 도구**

| 도구 | 하는 일 |
|---|---|
| `get_context` | 폴더 절대 경로, 페이지 목록, 디자인 시스템 내용, 보이는 페이지, 선택한 요소(선택자·HTML) |
| `checkpoint` | 고치기 전 스냅샷. 브라우저 [되돌리기] 와 같은 스택 |
| `undo` | 마지막 스냅샷으로 복원. 그 뒤 생긴 페이지는 지운다 |
| `open_page` | 연결된 브라우저에 페이지를 연다. 브라우저가 없으면 오류 |
| `screenshot` | 렌더 결과 PNG. Chrome 이 있을 때만. 내장 provider 에는 이 도구만 둔 `/mcp/render` 로 건넨다 |

### 3.5 데이터 저장

```
<디자인 폴더>/

  *.html                    페이지 (루트만)
  assets/                   이미지·폰트. 유일한 하위 폴더. 스냅샷에 넣지 않는다
  .hunsu/session            대화 ID (provider 가 준 값 그대로)
  .hunsu/history/000001/    요청·checkpoint·복원 직전 스냅샷 (최근 50개)
  .hunsu/versions/000001/   버전: files/, meta.json(시각·이름·대표 페이지·해시), thumb.png (최근 100개)
```

- (v1) 버전 타임라인, provider 별 대화 ID 가 `.hunsu/` 의 형식을 바꾼다. 형식은 미정.

## 5. Cross-cutting concerns

### 5.1 보안

전제: 로컬 단일 사용자. 공격자는 사용자가 연 다른 웹사이트, 또는 디자인 파일 안의 내용이다.

| 위협 | 현재 | (v1)·한계 |
|---|---|---|
| 원격 접속 | `127.0.0.1` 만 바인딩 | - |
| 다른 사이트가 localhost API 호출 (CSRF) | `/mcp` 토큰(상수 시간 비교), `/api/ui` Origin 검사. 나머지 API 는 미보호 | 마일스톤 4: 나머지 API 에 Host·Origin |
| DNS rebinding | 토큰이 있는 `/mcp` 외에는 미보호. `/api/ui` 의 Origin 검사도 Host 헤더와 비교한다 | 마일스톤 4: Host 검사 |
| 가짜 선택 요소로 에이전트에 지시 주입 | `/api/ui` 는 같은 출처만 받는다 | Host 검사 전까지 rebinding 에 열려 있다 |
| 폴더 밖 파일 접근 | 파일 API: 이름 규칙 + 일반 파일 + `os.Root`. claude provider: `--restricted` + `Read,Edit,Write` 만. 상대·절대 경로, 심볼릭 링크 모두 차단 확인 | API 형 provider 는 같은 보장을 provider 안에서 한다 |
| 디자인 파일 속 프롬프트 주입 | provider 격리로 피해 범위를 디자인 폴더 안 편집으로 한정한다. 명령 실행 없음 | 외부 HTML·에셋을 들이면 커진다 |
| 디자인 JS 가 hunsu API 호출 | 미보호. iframe 이 같은 출처다 | 외부 HTML 을 들일 때 포트를 분리한다 |
| 자격 증명 | hunsu 는 API 키를 갖지 않는다. MCP 토큰은 0600 파일. 시작할 때 터미널에 출력된다 | - |

### 5.2 프라이버시

- hunsu 자체는 외부로 아무것도 보내지 않는다.
- 디자인 파일·요청·선택한 요소는 provider 를 거쳐 LLM 제공자에게 간다. 무엇을 보내는지는 3.3 프롬프트 구성이 전부다.
- MCP 클라이언트는 토큰이 있으면 `get_context` 로 폴더 절대 경로와 디자인 시스템, 선택한 요소를 받는다.

### 5.4 관측성

- 사용자에게 보이는 것이 관측성의 전부다: 단계, 회전 표시, 경과 시간, 쓰는 파일과 크기(1KB 단위). 이벤트가 없는 구간(opus 17초)에도 시간이 올라간다.
- 실패하면 provider 의 stderr 를 오류 메시지에 담아 채팅에 보인다.
- hunsu 는 로그 파일·메트릭을 남기지 않는다. 터미널에는 주소와 MCP 정보만 나온다.
- 공백: 요청별 비용·토큰·시간 기록이 없다. 측정은 스파이크로 따로 한다 (`PLAN.md` 11). (v1) 타임라인이 시각·요청을 남긴다.

### 5.5 테스트 전략

- TDD. 실패하는 테스트 없이 제품 코드를 쓰지 않는다. 버그는 재현 테스트부터.
- 테이블 테스트가 기능 설명서다. 행 이름은 동작을 서술하는 한국어 문장이고, 할 수 없는 것도 행으로 둔다. JS 는 `table(t, rows, check)` 로 같은 형태.
- 실제 LLM 은 부르지 않는다. 핵심 패키지는 `llm.Provider` 대역, claude provider 는 testdata 의 가짜 실행 파일(정상, 편집, 실패, 멈춤).
- 프론트엔드는 DOM 을 얇게 두고 판단 로직(배치, 확대, 선택자, 도구, 진행 문구, 파일 반응)을 순수 함수로 빼서 `node --test`.
- 외부 도구(CLI, 브라우저, 표준 라이브러리)의 동작은 테스트하지 않는다. 스파이크로 확인해 `PLAN.md` 11 에 남긴다. 측정 기준은 claude 2.1.295 라 CLI 가 바뀌면 다시 잰다.

## 7. 미결 사항

1. **provider 선택 주체** (마일스톤 11). "고르는 곳은 `main.go` 하나" 와 "provider 선택" 의 관계. 런타임 선택이면 `main.go` 는 목록을 등록하고 `chat` 이 고른다. `.hunsu/session` 은 provider 별로 나뉜다.
2. **비교안 생성 방식** (마일스톤 12). 한 실행에서 여러 파일을 쓸지, 여러 실행을 돌릴지. "프로젝트당 하나만 실행" 과 단일 대화 규칙과의 관계.
3. **`[알림]` 의 재시작 공백**. 파일 해시가 메모리에만 있어, 서버 재시작 사이에 사용자가 고친 페이지는 이어진 대화에 알리지 못한다. 디자인 시스템만 전체를 다시 보낸다.
4. **동시 편집**. 외부 에이전트의 편집과 브라우저 채팅 실행 사이에 잠금이 없다.
5. **빈 프로젝트의 파일 목록**. 프롬프트에 넣으면 없는 파일을 읽는 4초를 줄일 수 있다고 측정했지만 마일스톤에 없다.
6. **Codex provider 의 동등성**. 격리, 폴더 밖 차단, 부분 스트리밍이 claude provider 와 같은 수준인지 아직 재지 않았다.
